# Session: freezing a todo — "will not do"

Session ID: `dd62e1e7-1e9d-4046-a8f5-cec61cd095ba`
Date: 2026-08-04

One line of ask:

> "I want the ability to freeze a todo (meaning will not do)"

No plan mode. Read `store.go`, `ui.go`, `fuzzylist.go`, `styles.go` and the
README directly, then settled the two decisions that would have changed the
shape of the work before writing anything.

## The two questions

**Where a frozen row sits.** Three options offered with rendered previews;
chosen: *its own group, folding with done*. Order within a scope becomes
open → frozen → done, and `ctrl+d`'s fold widens to take both closed states.
Rejected: leaving it in place among the open rows (it never gets out of the
way, which is the whole point), and filing it with the completed ones (a
frozen prompt amongst ticks reads as finished).

**What freezing does to drop and schedule.** Chosen: *block both, explain
why*. `shift+enter` is one keystroke from every row in the list — including
the ones that slide under the cursor after a rebuild — so a decision not to
do the work has to survive a stray press.

## Why a separate flag and not `Done`

The state that already existed could have carried this: mark it done, move
on. It cannot. `Done` claims the work happened, and a backlog that says so
about work nobody ever did is a backlog that lies — every later reading of
it (the pane title's count, the completed pile, `ctrl+w`) inherits the lie.
Deleting the prompt is the other cheap answer and throws away the fact that
the decision was made at all, which is usually the thing worth keeping.

So: three states, mutually exclusive, exactly one group per todo.

```
open    ○  descStyle     still to do
frozen  ❄  colInfo       decided against, kept on the record
done    ✓  checkStyle    finished
```

## `store.go`

- **`Todo.Frozen bool`**, `json:"frozen,omitempty"` — the same compat
  contract `Images` and `Schedule` carry: absent from the JSON when false, so
  an unfrozen backlog serialises byte-identically to before and an older
  binary reads a plain open todo rather than choking. Pinned by a test that
  greps the written file for the key.
- **`Todo.group()`** → `groupOpen | groupFrozen | groupDone`, the render
  order and nothing else (not stored, so it can be reordered freely). `Done`
  outranks `Frozen` so a hand-edited backlog claiming both still lands in one
  group — the renderer walks the groups in separate passes and a todo
  answering yes twice would be drawn twice.
- **`Todo.closed()`** = `Done || Frozen`. Everything asking "is there work
  here" asks it this way: the fold, the header's hidden count, the pane
  title's open count, the schedule tick. Only the row itself tells the two
  apart.
- **`toggleFrozen(id) (bool, error)`** returns the state it *landed in*
  rather than letting the caller infer it from what was on screen. The flip
  happens after a `reload()`, so another pane may have frozen or thawed the
  todo since this one drew the row — a status line reporting the caller's
  guess would be confidently wrong exactly when the panes disagree.
  `setFrozen(id, bool)` is the idempotent sibling; both go through a shared
  `freeze(i, bool)`.
- **Exclusivity, both directions** — freezing clears `Done` and any pending
  schedule (a prompt nobody intends to run must not run itself); `toggle`
  and `setDone` clear `Frozen` on the way to done.
- **Array position is deliberately untouched** — the one place freezing
  differs from completing. `fileAsLatestDone` moves a finished todo to the
  head of the done pile; a frozen one has not happened, it is still work
  holding its place in the priority order, so a thaw hands it back the
  position it had instead of dropping it at the end of the open group.
- **`move`** now matches on `group()` instead of `Done` alone: swapping a
  done todo with the frozen one above it would move the row nowhere the user
  can see, since the two are drawn in different passes.
- **`clearDone` untouched**, and that is the point — the sweep for finished
  work must not quietly throw away a decision the user asked to keep.
  Deleting a frozen prompt stays a deliberate `ctrl+x`.

## `ui.go`

- `hideDone` → **`hideClosed`**; `hiddenDoneCount` → **`hiddenClosedCount`**.
  One fold, not two: the question it answers is "show me what is left to do",
  and a prompt decided against is no more left to do than a finished one.
  Header note drops the word: `· N hidden`, since naming one of the two
  states would misreport the other half of the number.
- **New `doneCount()`** — `beginClearDone` used to borrow `hiddenDoneCount`,
  which now includes frozen. Without the split, `ctrl+w`'s confirm would have
  promised to delete prompts it does not touch.
- **`rebuildList`** walks one pass per group in render order, returning early
  on the closed groups when the fold is on. Three passes over the slice is
  what keeps the grouping in the *view* rather than in the file — the array
  stays the user's priority order.
- **`ctrl+f` → `freezeSelected`** — reads the todo *before* the flip (a
  freeze cancels a pending schedule, and afterwards the row shows nothing to
  say the auto-drop went with it), re-parks the highlight on the row since it
  moves down a group or out of sight entirely, and reports which way it went.
  Status: `frozen — will not do (ctrl+f to unfreeze) · scheduled drop cancelled`.
- **Guards.** `startDrop` covers both ways in (list `shift+enter` and the
  view stage's), `beginSchedule` keeps the same rule from the other side so
  it cannot be worked around by scheduling first and freezing after.
  `fireDueSchedules` now skips on `t.closed()` — a backstop for a backlog
  edited by hand or written by a binary that predates the invariant, where
  firing would be the worst possible reading.
- **`openCount`** (the pane title's `todo: cats (3)`, which cats' sidebar
  reads to mark a workspace as holding work) excludes frozen — the number is
  read as "work waiting here", and the point of freezing is that it isn't.
- Prompt view meta line gains `· frozen — will not do`.
- Footers gain `ctrl+f freeze` directly after `ctrl+t done` — the two ways a
  prompt leaves the open list, read side by side, which is what teaches that
  they are different claims. `hide done` → `hide closed`.

## Rendering — dim, not struck

`listItem` gains **`dim`** alongside `strike`, and `highlightName` takes it
as a fifth argument (`strike` wins if both are somehow set — a finished todo
reads as finished first). New `frozenStyle`/`frozenSelStyle` reuse the done
greys, including the one-tier lift under the cursor, so a frozen row being
looked at doesn't recede into the field.

The strike is the thing that had to go. It is a claim the work was carried
out, which is precisely what freezing does not say. Dim carries "not active
work"; the badge says which kind.

`frozenBadgeStyle` is **colInfo** — the palette's one cool hue, borrowed from
the Add chip. Cold is the idea, and it makes the three badges separable at a
glance: green ✓ finished, amber ◷ pending, blue ❄ shelved. Grey was the other
candidate and is wrong: the row's own greys already say inactive, so a grey
badge would repeat the name's tier instead of naming which kind of inactive.

Verified by rendering the list to a string in a throwaway test (deleted
after), which is also how the footer concession below was caught:

```
❯ ○ fix the flaky reconnect  the ws drops
  ○ rewrite the drop picker  too many rows
  ❄ port to bubbletea v1     not happening      ← dim, no strike
  ✓ a̶d̶d̶ ̶g̶l̶o̶b̶a̶l̶ ̶t̶a̶g̶            done already
```

## Tests

- `TestFreeze` — seven subtests: toggle reports its landing state,
  schedule cancellation, exclusivity both directions, `setFrozen`
  idempotence + `errTodoNotFound`, position held across freeze/thaw, JSON
  round-trip *and* absence of the key when false, `clearDone` leaves frozen
  alone, `move` stays inside the group.
- `TestFreezeSelected` — `ctrl+f` through `updateList`: persists, the row
  drops below the open one, the highlight follows it, the status reports it,
  and a second press returns it to its original place.
- `TestFrozenPromptsRefuseToLeave` — table over `shift+enter` and `ctrl+s`,
  with a live `client` set so the refusal cannot be the socket guard passing
  for the frozen one. Asserts the status names both the state and the way out.
- `TestHideDoneFoldsCompleted` → `TestHideClosedFoldsCompletedAndFrozen`,
  extended to pin the open → frozen → done row order and the
  `hiddenClosedCount` / `doneCount` split.
- `highlightName` call sites updated; new subtest pins "a frozen row recedes
  without a strike" and that it doesn't render identically to an open one.

Suite, `go vet`, `gofmt` all green.

## Left on the table

The wide-pane footer concedes segments from the right when it overruns.
`ctrl+f freeze` plus `hide done` → `hide closed` costs ~15 columns, so at 100
columns it now drops `ctrl+w clear done` *and* `esc quit` where it previously
dropped only `esc quit`. Those are the two least valuable segments and the
ordering was already chosen for that, so the mechanism was left alone —
flagged to the user rather than fixed by shortening labels.
